# Security model and verification limits

The trusted local UI controls folder and connection grants. Fixed typed Electron IPC validates the main-window sender and top-level frame; the renderer remains sandboxed, isolated, and without Node integration. The authenticated agent accepts only a private Unix socket or Windows named pipe, never TCP. Scoped MCP credentials cannot call administrative methods.

Read only, Reviewed and Workspace Full Access are independent per-connection/per-folder settings. Effective rights intersect folder flags, connection grants and enabled modules. Catalog visibility and execution recheck current rights. Full Access applies file writes and queues commands immediately after explicit folder authorization; Reviewed retains local approval. **All commands use the native sandbox, including Reviewed commands.** There is no unrestricted fallback on native failure.

Seatbelt on macOS and the native Windows LPAC helper isolate the current workspace, necessary read-only runtime files, and separate HOME/cache/temp paths. Bootstrap initialization runs inside that boundary. Agent/tunnel keys are excluded from environment and private app state is denied. Public TLS certificates are copied independently of private keys. Managed dev servers bind loopback; macOS additionally restricts network binding in Seatbelt. Network egress is allowed for development dependencies/services.

File tools reject traversal, absolute paths, symlinks/junctions, hard links, protected secret/metadata paths, ambiguous Windows device/stream names, and root replacement/deletion. macOS workspace identities bind the opened directory's volume UUID, inode and birth time; mount-time device numbers are not persisted in new Mac grants. Other platforms bind device/inode/birth time. Matching legacy identities migrate on a trusted local snapshot; mismatches require original-folder selection and native confirmation through Re-authorize folder. Recovery preserves existing grants, rechecks the selected identity, stops owned work, rejects pending changes and records an audit entry. MCP clients cannot perform recovery. Full Access mutations execute in a sandboxed worker, with hash preconditions, byte-preserving snapshots and safe conflicting Undo. Tree replacements stage complete content before replacement. Reviewed legacy text edits retain the prior local-review path; its ancestor-rename TOCTOU hardening remains a separate release concern. File checkpoints are limited, and command effects have no universal Undo.

Jobs retain actual logs, exit codes, timeouts, cursors and idempotency. Cancellation/revocation terminate owned process groups on macOS and process trees/Job Objects on Windows. Native launch manifests retain birth identity rather than trusting a persisted PID alone. Startup recovers those launches and interrupts running/queued records without replay. Windows cleanup removes only its unique per-launch SID ACEs and loopback exemption; failures retain the manifest for retry and are recorded in agent logs. macOS uses native sub-second process birth identity and per-launch isolated Seatbelt capabilities to census and stop detached/reparented owned descendants. Missing parents are not ownership evidence; private markers and control descriptors certify the scope.

Browser automation runs in an outer native sandbox and uses private Playwright pipes. Each owned session has a new context, controlled actions and managed-preview-only navigation. Chromium’s inner sandbox is disabled because Seatbelt cannot be initialized twice; the outer workspace policy remains mandatory. No browser is launched outside it. Browser routes block external navigation and other private-address requests; network egress itself is still development-enabled. A native browser security review remains a release gate.

Git hooks, external diff/text conversion and global config are disabled. Git metadata symlinks/hard links, external alternate stores, linked worktrees and config includes are rejected. General terminal commands retain the same native filesystem scope.

Tunnel keys are OS-encrypted with safeStorage, excluded from renderer/preload and bridge environments, and passed only to the official outbound runtime. Runtime, local MCP handshake, OpenAI polling and actual ChatGPT calls are distinct evidence. Runtime ready alone does not prove a ChatGPT account connection. After metadata changes, Refresh tools and start a new ChatGPT chat.

This preview is unsigned and not notarized. Local MCP credentials still use private files; Windows credential storage/ACL review, Windows execution, Intel Mac, clean-install tests, and a production security audit remain required. Quit stops agent/tunnel by default. Opt-in source background survival is exercised; packaged login/reboot lifecycle and Windows registration remain separate certification gates. See WORKSPACE-FULL-ACCESS.md and WINDOWS-VERIFICATION.md for the current workflow and platform handoff.

Plans/attempts/artifacts are client/workspace-scoped. Completion requires actual verification; source or bound-environment changes stale the relevant proof. PNG/JSON evidence is immutable and integrity-checked. Skills are inert imports with bounded reads/archives, scoped discovery and content-hash authorization; allowed-tools cannot grant extra rights. Project plugins are not loaded into the source index worker.

The services and built UI used by an active app are frozen, hashed copies. A changed agent build or bridge catalog is surfaced as an explicit mismatch, without silently stopping existing jobs. Retained revisions stay available to old configurations. Active HMR app source is protected from scoped writes; use a built UI to edit Remote Studio itself. Windows refuses workspace overlap with the active runtime because the inherited write ACL cannot safely provide a read-only overlay.

Environment values use the OS-backed vault, remain ephemeral in the agent and are bound to explicitly selected jobs/clients. Locked/corrupt vaults preserve ciphertext and fail closed. Separate stdout/stderr redactors hide configured plaintext values across chunks. Arbitrary authorized project code can use injected secrets, including encoded/network output; this is not a general exfiltration prevention system. Support bundles whitelist diagnostics and omit source, paths, logs, argv and secret values.
